# 数据导入与校验台账

用于本地来源数据导入与校验记录管理的命令行项目。

需要 Python 3.12，无第三方依赖。在仓库根目录运行：

```bash
python3 -m import_pipeline --help
python3 -m import_pipeline --version
python3 -m unittest discover -s tests -v
```

无参数显示帮助，未知参数以非零状态退出。

## 配置子命令

所有配置持久化到仓库根目录的 `import_ledger.db`（SQLite，标准库管理），这是唯一的持久化文件。成功操作在 stdout 打印一行 `Result: <操作> <来源名> <条目数>`；业务规则拒绝（如重名、冲突）退出码为 1 且不落库，用法错误（未知子命令、缺失参数）按 argparse 约定退出码为 2，错误信息均写 stderr。

```bash
# 注册来源配置：来源名（唯一）、CSV 路径、至少一个必需字段名（非空、不重复）
python3 -m import_pipeline add-source orders data/orders.csv id amount

# 注册字段映射：来源名、源列名、目标列名；同一来源下源列名唯一
python3 -m import_pipeline add-mapping orders order_id id

# 只读查询：列出全部来源（来源名、路径、逗号连接的字段列表，制表符分隔）
python3 -m import_pipeline list-sources

# 只读查询：列出某来源的字段映射（源列名、目标列名，制表符分隔）
python3 -m import_pipeline list-mappings orders
```

校验规则：来源名、路径、字段名、列名均须为非空字符串；布尔与状态字面值只接受小写 `true`/`false`/`ok`/`failed`/`rejected`，大小写不同（如 `TRUE`）视为非法输入并拒绝。重复注册来源名、重复字段名、同一来源下重复源列名、引用不存在的来源均被拒绝，且数据库保持执行前状态（单次操作原子提交）。

## 批次导入

```bash
# 执行一个批次的导入：读取来源登记的 CSV，按字段映射逐行导入
python3 -m import_pipeline import orders
```

CSV 首行为表头，数据行按表头取值，不作 trim 或大小写转换，空值原样保留。每行按映射后的目标字段名（字典序升序）拼接 `目标字段名=原值` 并以 `&` 连接，取 sha256 作为签名；与该来源此前任意批次已导入成功的记录签名相同则判为重复并丢弃，否则正常导入并计为增量新数据。成功行须包含来源声明的全部必需字段且值非空，否则与缺少表头、列数与表头不一致的行一样记为校验失败，隔离到当前目录的 `rejected_<来源>_<批次号>.csv`（字段顺序与原 CSV 一致，按文件内出现顺序写出），失败行不导入。

批次记录持久化到 `import_ledger.db`：批次号（同一来源下从 1 递增）、来源名、总行数、成功导入数、重复丢弃数、校验失败数、增量新数据数。成功时 stdout 打印一行：

```
Result: import <来源名> <批次号> <总行数> <成功导入数> <重复丢弃数> <校验失败数> <增量新数据数>
```

来源未注册、CSV 不存在或无法读取、CSV 含未映射目标列、必需字段未全部映射时，错误信息写 stderr，退出码为 1，且不产生批次记录、拒绝文件或任何数据库变更。同一来源可多次导入，批次号始终递增。

## 批次操作

```bash
# 查看某来源的全部批次（只读）：按批次号升序，每批一行、制表符分隔
# 列为：批次号、总行数、成功导入数、重复丢弃数、校验失败数、增量新数据数
python3 -m import_pipeline batches orders

# 显式重跑指定批次：沿用现有导入的全部行语义，但不新建批次
python3 -m import_pipeline reimport orders 2

# 撤销指定批次：删除批次记录及其当时新增的导入记录签名
python3 -m import_pipeline rollback orders 2
```

`batches` 为只读操作，每行各列以制表符分隔，末尾再打印一行 `Result: batches <来源名>`。来源未注册时错误写 stderr、退出码 1；来源已注册但无批次时不输出批次行、仅打印 Result 行，退出码 0。

`reimport` 读取来源当前登记的 CSV 重新跑一遍指定批次：签名判重仍按同来源**当前全部**已导入成功记录比较，因此被重跑批次自身此前导入的签名也参与判重，失败行沿用相同的列数与必需字段校验并隔离到该批次号的拒绝文件。它不新建批次，而是在单个事务中删除该批次名下的旧签名、用本次结果整体更新批次计数并写入新签名，批次号保持不变，其他批次不受影响。预检失败（来源未注册、CSV 问题、映射问题）或目标批次号不存在时，错误写 stderr、退出码 1，且不改动任何记录与文件。成功时打印：

```
Result: reimport <来源名> <批次号> <总行数> <成功导入数> <重复丢弃数> <校验失败数> <增量新数据数>
```

`rollback` 删除指定批次的批次记录，以及 `imported_records` 中归属该批次的签名——仅该批新增的签名被删除，更早批次及其他批次的签名保留（被删签名对应的记录此后可再次作为增量导入）；不产生拒绝文件。来源未注册或目标批次号不存在时错误写 stderr、退出码 1 且无任何变更。成功时打印一行，末尾的总行数取自被删除的批次记录：

```
Result: rollback <来源名> <批次号> <总行数>
```

`reimport` 与 `rollback` 的批次号必须是十进制正整数（不接受 `0`、负数、前导零、小数等写法）；非法写法按用法错误处理，退出码为 2。三项操作仍只使用唯一持久化文件 `import_ledger.db`，所有拒绝行只写拒绝文件、不落库。

## 行复核

导入中可疑行（列数与表头不一致或必需目标字段缺失，判定先于判重）直接进入拒绝文件，可通过行复核流程人工救回：

```bash
# 导出指定批次的可疑行供人工修复
python3 -m import_pipeline fix-rejects orders 3

# 应用人工修复结果
python3 -m import_pipeline apply-fixed orders 3
```

`fix-rejects` 的批次号规则同 `reimport`。批次须存在且由 `import` 创建（reimport 批次报错、退出码 1、无任何变更）；可疑行数为 0 同样报错、退出码 1、不生成文件。否则重写当前目录的 `rejected_<来源>_<批次号>.csv`（表头加可疑行、原样按出现顺序），并生成同目录 `rejected_<来源>_<批次号>_fix.csv`：表头为原表头追加空列 `fix_result`（原表头已含 `fix_result` 时追加首个不冲突的 `fix_result_N`，N 从 1 起），可疑行原样在前、`fix_result` 留空。该命令不改动批次计数与签名。成功时打印：

```
Result: fix-rejects <来源名> <批次号> <可疑行数>
```

人工编辑修复文件：修正行数据并将 `fix_result` 列填为小写 `ok`（修复后导入）或 `rejected`（确认拒绝）。`apply-fixed` 校验该列只接受这两种取值，其他取值或缺列报错、退出码 1 且无任何变更。`ok` 行重新做行校验（仍不过关则整体报错、退出码 1、无任何变更），再按同来源全部历史已导入签名判重：命中计重复丢弃，否则导入为增量新数据；`rejected` 行写回 `rejected_<来源>_<批次号>_fix.csv`（表头与原 CSV 一致、按修复文件出现顺序，无 rejected 行则不生成）。整批在单事务中更新批次计数（总行数不变，成功导入数与增量新数据数各加修复成功非重复行数，重复丢弃数加修复判重行数，校验失败数减本次处理可疑行数）并写入新签名，批次号不变。成功后删除修复文件，原 `rejected_<来源>_<批次号>.csv` 始终保留。批次不存在、未经 `fix-rejects`、修复文件缺失时错误写 stderr、退出码 1 且无任何变更。成功时打印：

```
Result: apply-fixed <来源名> <批次号> <修复成功数> <重复丢弃数> <拒绝数>
```
